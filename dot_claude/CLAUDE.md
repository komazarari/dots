# Global Guidelines

## 外部ライブラリの調査
外部ライブラリの使い方を調べるときは **Context7 MCP** を使い、信頼できる最新情報を取得すること。

## 箇条書きの識別 ID
個別に言及される可能性がある箇条書き（確認事項・候補・選択肢など）には「絵文字＋アルファベット＋番号」を振る。

- 形式例: `🍓 K1.` `🍓 K1a.` `🍓 AA1.`
- 同グループは同じ絵文字、異なるグループは別の絵文字
- アルファベット「S」は Amazon S3 との混同を避けるため使用禁止
- 参照頻度が低い項目・通常の会話には不要

## 禁止された破壊的操作の承認
組織ポリシーで rm などが拒否されることがある。しかし検証用や一時ファイルなど無害と判断できるものの削除など、拒否される操作の実行が合理的と考えられる場合はユーザに操作または承認を依頼してよい。

## コーディングガイド
コード自体には How, テストコードには What, コミットログには Why, コードコメントには必要なら Why not を書くように心がける。特に、普遍的な正当性の無いコメントを増やしすぎないこと。 
コメント言語は基本的に英語を用いる。ただしファイル内で既に日本語が使われている場合は統一性を保つため日本語で良い。(Code commments should be written in English. However, if existing comments in the file are written in Japanese, maintain consistency by writing them in Japanese as well.)
コードコメント, docblock は stock であり、書いた時点の文脈を知らない読み手が読む。「隣のクラスを誰かが書き換えたら、このコメントは嘘になるか」を基準に、嘘になる内容 (他クラスの実装詳細、調査の経緯、一回性の事情) はコミットログや `docs/` などの専用のドキュメントへ逃がす。
